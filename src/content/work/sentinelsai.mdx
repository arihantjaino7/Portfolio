decision:
  question: What writes the fix?
  chose: Deterministic Python patchers, with the model kept out of the write path
  rejected:
    - An LLM generating the patch directly
    - An LLM generating the patch behind a human approval step
  why: >-
    A security fix that is right most of the time is not a security fix. A model asked
    to rewrite an nginx config will produce something plausible every time and something
    correct most of the time, and the failure mode is a change that looks fine in review
    and quietly widens the hole. Putting a human gate in front of it only moves the
    problem: reviewers approve plausible diffs. So the patchers are ordinary Python —
    each one handles a finding type it fully understands, and refuses anything outside
    that. Every change is rendered as a diff before a byte is written and lands on a
    branch as a pull request, never on main. The pipeline fixes less than an LLM would
    claim to, and everything it does fix is verifiable by reading the patch.

The eight agents run under a single `asyncio.gather`, so total scan time is bounded by
the slowest agent rather than their sum. Each returns findings in a common shape, which
is what makes the scoring layer possible at all.

Score deduplication matters more than it sounds. A missing security header shows up in
the header agent, the API agent, and the misconfiguration agent; scored naively, one
mistake costs a target three penalties and the grade stops meaning anything. Decay
handles the same class of problem across severity tiers.
